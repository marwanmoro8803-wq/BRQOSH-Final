# ADR-001: اختيار المكدس التقني

**الحالة:** معتمد — قرار نهائي من المالك
**التاريخ:** 2026-07-05

## السياق

إعادة بناء كاملة لنظام BRQOSH ERP (النسخة السابقة: Python + Tkinter + SQLite).
المتطلبات الحاكمة:

- أفضل أداء ممكن: إقلاع سريع، استجابة فورية، تحمّل 5 مليون مدخل.
- برنامج Desktop لنظام Windows يعمل بدون إنترنت.
- امتثال سعودي: ZATCA Phase 2، ضريبة القيمة المضافة 15%.
- عربي RTL أولاً.
- منافسة برامج المحاسبة العالمية (QuickBooks، Tally، SAP B1).

## البدائل المرفوضة

- **البقاء على Python/Tkinter:** سقف واجهة منخفض، إقلاع أبطأ، انطباع غير enterprise. رفضه المالك صراحة.
- **Rust/C++:** أداء أعلى نظرياً لكن تطوير أبطأ 3–4x ومكتبات ERP أفقر؛ عنق الزجاجة الفعلي هو قاعدة البيانات وليس اللغة.
- **Electron:** استهلاك ذاكرة ضخم وإقلاع بطيء — يناقض المتطلب الأساسي.
- **SQL Server Express:** حد 10GB يمنع هدف 5M+ سجل بدون ترخيص مدفوع.

## ما نرثه من النسخة القديمة (كمرجع تصميم، لا كود)

- منطق ZATCA Phase 2 (UBL XML، سلسلة الهاش، QR TLV) — يُعاد تنفيذه بـ C#.
- مخطط قاعدة البيانات (schema_engine) — أساس تصميم الجداول الجديد.
- مصفوفة الأنشطة → الوحدات (module_registry) — تُنقل كما هي مفهومياً.
- الترجمات العربية (568 نص) — تُنقل إلى ملفات موارد .resx/JSON.
- مصفوفة الصلاحيات والأدوار.
