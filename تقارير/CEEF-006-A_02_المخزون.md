## Current vs Best Practice

| البند | الحالي | أفضل ممارسة ERP | التوصية |
|-------|--------|-----------------|---------|
| On-hand | `inventory_balances` | جدول رصيد + ledger | ✅ صحيح |
| WAC | شركة-wide؛ ترتيب cost ثم qty | per-line interleave أو batch receipt | إصلاح ترتيب التطبيق |
| Transfer | مسار UI منفصل | نفس PostingService + UoW | توحيد المسار |
| COGS reversal | WAC لحظي | cost من حركة البيع | ربط بـ `SalesInvoice` movement |
| Multi-WH | default only | اختيار مستودع في المستند | توسيع Domain |

## ما هو سليم (مُثبت)

- منع الرصيد السالب عند الترحيل (`InventoryCycleTests`, `TransactionAtomicityTests`).
- حركات المستندات لا تُلغى من شاشة المخزون (`SourceDocument` guard).
- إلغاء فاتورة مبيعات يعيد تكلفة السطور الأصلية (`SalesInvoiceCancellationService.cs:56-62`).
- `GetOnHandAsync` O(1) عبر balances (`InventoryPerformanceTests` 1000 حركة).

## Test Cases حرجة

1. Transfer persistence (P0).
2. Receipt نفس الصنف سطرين بأسعار مختلفة → WAC متوقع.
3. Purchase → cancel → WAC=0 أو معاد حساب.
4. Sale → تغيير WAC → credit note → COGS = COGS البيع.
5. Stock count: qty نظام 0، فعلي 5 → AdjustmentIn.
6. Stock في WH-2 فقط → بيع من default → فشل متوقع.
